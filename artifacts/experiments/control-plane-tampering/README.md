# Trust-Boundary Hardening — Worker-Side D→P Validation (Task 11)

Optional task, addressing experiment protocol Q15 and section 13. **Read
`summary.md` first**: it documents the problem (per the protocol's
explicit "before changing architecture, document the problem"
instruction), what was implemented, and the experimental result (5/5
correct-P accepted, 5/5 tampered-P rejected, with the rejection confirmed
to actually reach the kernel eBPF maps, not just the logs).

## Directory layout

- `raw/results.jsonl` — all 10 records (5 per condition).
- `raw/exec-rules-map-after-tamper.json` — direct `bpftool map dump`
  ground truth proving a tampered policy's rogue rule never reached the
  kernel.
- `processed/` — `results-raw.csv`, `summary.csv`, generated by
  `scripts/analyze.py`.
- `figures/verdict-rates.png`.
- `scripts/lib.sh`, `run-experiment.sh`, `analyze.py`.
- `environment.json`, `experiment-config.json` — provenance, RBAC change,
  full mechanism description.
- `summary.md`, `exclusions.md`.

## What was implemented

`ebpf-agent/internal/trustverify` (new package) — independently verifies
each `RuntimeSecurityPolicy` against its source `AIPlacementDecision`
before the agent trusts it: signature verification (reusing the
operator's own `pkg/token.VerifyForPod`), a from-scratch local
recomputation of the expected policy hash compared against the actual
received policy's hash, anti-replay/anti-rollback, and pod-UID/node-
identity binding. On failure, the agent applies a safe deny-all plan
instead of the received (untrusted) content. Wired into
`ebpf-agent/cmd/agent/main.go`'s existing reconcile loop; RBAC additions
in `deploy/azure/cpu-campaign-20260813/manifests/agent-daemonset.yaml`.

## Reproducing

Requires a live cluster matching `environment.json` (the Task 11 agent
image, with the new RBAC applied) and the trust-anchor secret under
`deploy/azure/cpu-campaign-20260813/.run/secrets/`.

```
cd scripts
bash run-experiment.sh   # ~5-8 min (5 reps x 2 conditions)
python3 analyze.py
```

Unit tests for the core hash-comparison and anti-replay logic:
`cd ebpf-agent && go test ./internal/trustverify/... -v`.
