# Experiment G — Real BPF-LSM Enforcement on CPU (Task 10)

Addresses experiment protocol Q14 and G1-G3. **Read `summary.md` first** — this
experiment has both a genuine positive result (real BPF-LSM programs load,
verify, and correctly gate the allow path on this hardware, plus three
previously-latent bugs found and fixed to get there) and a genuine,
honestly-reported negative result (pre-effect denial was not observed
despite confirmed-correct kernel-side configuration). `exclusions.md` has
the full diagnostic trail for both.

## Directory layout

- `raw/` — `g1-results.json` (120 individual probe records: exec/file/
  network × allow/deny × n reps), `g1-warmup-diagnostic.txt` (stderr trace
  of the runner's self-diagnosing warm-up loop), `ebpf-map-groundtruth.txt`
  (live `bpftool map dump` output for `cgroup_configs`/`exec_rules`),
  `lsm_exec_xlated_bytecode.txt` (`bpftool prog dump xlated` of the loaded
  `lsm_exec` program).
- `discarded-runs/` — three earlier G1 attempts invalidated by harness bugs
  (not by RuntimeGuard), each with its own root cause documented in
  `exclusions.md`.
- `processed/` — `g1-results-raw.csv`, `g1-summary.csv`, generated by
  `scripts/analyze.py`.
- `figures/` — `g1-allow-vs-deny.png`.
- `scripts/analyze.py` — regenerates `processed/`/`figures/` from `raw/`.
- `environment.json`, `experiment-config.json` — machine-readable
  provenance: exact GRUB/kernel state before and after, image digests, the
  G1/G2/G3 parameters and scoped conclusions.
- `summary.md`, `exclusions.md` — the human-readable writeup.

## New tools built for this task

- `operator/cmd/lsm-probe` — single-shot exec/file/connect probe with
  precise errno capture, used for initial interactive diagnosis (before
  discovering `kubectl exec` itself gets denied under enforce-mode — see
  `exclusions.md`).
- `operator/cmd/g1-runner` — the actual G1 test suite, running AS the
  pod's own entrypoint process (required once enforce-mode is active; see
  `exclusions.md`), with a self-diagnosing warm-up loop instead of a fixed
  wait.
- `ebpf-agent/Dockerfile.gen-bpf` — throwaway multi-stage build used to
  regenerate `internal/bpfobjs/agent_x86_bpfel.{go,o}` against this
  worker's own live kernel BTF; not part of the final agent image.

## Reproducing

Requires a live cluster matching `environment.json`, INCLUDING the
worker-node GRUB/reboot state (`bpf` in `/sys/kernel/security/lsm`) — this
is not achievable by redeploying manifests alone.

```
# One-time, already applied to this cluster's worker node (see environment.json):
#   GRUB_CMDLINE_LINUX += lsm=lockdown,capability,landlock,yama,apparmor,bpf; reboot

cd scripts
python3 analyze.py   # regenerate processed/figures from the retained raw/ data
```

Re-running G1 live requires minting a decision + patching a
RuntimeSecurityPolicy to `enforcementMode: enforce` with a narrow
allow-list, then deploying `g1-runner` — see `exclusions.md` for the exact
sequence and the pitfalls already found (do this in one uninterrupted
sequence; a slow `go run` in between minting and patching was the proximate
cause of one discarded attempt).
