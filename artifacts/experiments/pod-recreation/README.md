# Experiment D — Kubernetes Identity Regression (Task 07)

Addresses experiment protocol Q10 (does policy binding survive Kubernetes Pod
recreation with the same Name+Namespace and a new UID) and section 9's
regression/anti-pattern validation requirement. Explicitly **not** a claim
of novel contribution — this validates that an existing fix (commit
`487a57e`) still holds.

**Start here**: `summary.md` for the finding (10/10 pass, unanimous);
`exclusions.md` documents that no bugs were found and no runs were
discarded — the harness worked cleanly on the first attempt.

## Directory layout

- `raw/d1-pod-recreation.jsonl` — one JSON record per independent
  recreation trial (n=10).
- `processed/` — `d1-pod-recreation-summary.csv` (aggregate pass counts)
  and `d1-pod-recreation-per-rep.csv` (per-rep detail), generated by
  `scripts/analyze.py`.
- `discarded-runs/` — empty; no runs were invalidated in this task.
- `scripts/run-d1.sh` — the experiment script.
- `environment.json`, `experiment-config.json` — machine-readable
  provenance.
- `summary.md`, `exclusions.md` — the human-readable writeup.

No code changes were required for this task (unlike Tasks 05/06) — it
exercises a pre-existing fix, not new instrumentation.

## Reproducing

Requires a live cluster matching `environment.json` and the trust-anchor
secret under `deploy/azure/cpu-campaign-20260813/.run/secrets/`.

```
cd scripts
bash run-d1.sh   # ~10 min (10 reps x ~1 min each + final 20s wait + log capture)
python3 analyze.py
```
